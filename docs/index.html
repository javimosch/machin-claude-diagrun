machin-claude-diagrun

Where did your Claude Code tokens go? One native binary reads your local transcripts and answers in JSON, or as an HTML report.

Source Inspired by diagrun Built with machin

Quick start

You need machin and a C compiler.

git clone https://github.com/javimosch/machin-claude-diagrun
cd machin-claude-diagrun && ./build.sh
bin/diagrun guide --human
bin/diagrun scan --days 7           # JSON
bin/diagrun report --days 7         # ~/.diagrun/report.html

What it measures

SectionQuestion it answers
SpendWhat did each model cost at API list price, in the main conversation and in subagents?
Cache writesWas each write a first fill, new content, or a rebuild?
Idle rebuildsHow long was the pause, and what arrived before the next request?
Model fitWhich prompts might a cheaper model have handled? A lower figure and a ceiling.
Long contextWhat did re-reading beyond 100k and 150k tokens cost, at most?
Repeated workUnchanged re-reads, repeated commands and very large tool results.

Causes, task classes and triggers are inferred from token counts, timestamps and known transcript markers. Savings figures overlap, so do not add them. Prices are built into the binary and can go out of date.

Made for agents

guide and help-json describe the tool from the binary alone. Data goes to stdout; errors are typed, carry suggestions and use distinct exit codes. It follows the output, guide and relay-only feedback conventions of cli-specs. diagrun feedback reports who sent it as agent unless told otherwise. update and install are not implemented, and there is no telemetry.

Privacy

  • By default, output holds no prompt text, file names or commands.
  • --examples adds them. Commands may contain secrets.
  • The network is used only when you run report --publish (uploads to hart) or feedback (sends your text to a feedback relay; FEEDBACK_RELAY=off disables it).
  • Publishing with examples requires --private and a read key. An unlisted page is readable by anyone with its link.

Large histories

Transcripts are read in 4 MB chunks. On synthetic input, a single 1.6 GB file peaked at 640 MB of memory and took 13 s. Memory still grows with the number of lines. To run under a hard limit on Linux with systemd:

CAP=2G LIMIT=300 tests/capped.sh bin/diagrun scan --days 7

Origin

The idea comes from diagrun by François Nollet (MIT), a zero-dependency Node CLI that turns Claude Code logs into a readable diagnosis in French.

This is a new implementation in machin. It is not a clean-room implementation: the original source was read first, and the task-class rules, their patterns and several thresholds are adapted from it.

What is different here: JSON-first output, newer model prices, separate subagent spend, de-duplication of copied messages, cache-write causes, and prompts left out unless requested.
